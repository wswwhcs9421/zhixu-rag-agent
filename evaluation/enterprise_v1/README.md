# 企业制度 RAG 测试集 v1

已整理 **10 份资料、44 道问题**：40 道可依据资料作答，其中 4 道需要跨文档综合；另有 4 道资料不足题，检查模型是否编造公司规定。每题记录预期答案、必答要点、原文摘录、资料编号、条款、原 PDF 页码和官方链接。

## 来源与适用范围

来源是财政部[《企业内部控制配套指引》官方发布页](https://kjs.mof.gov.cn/zhengcefabu/201005/t20100504_291943.htm)所附[《企业内部控制应用指引》原始 PDF](https://kjs.mof.gov.cn/zhengcefabu/201005/P020230421440664863663.pdf)。保存了原 PDF 和 SHA256，可离线核对。

这是**同一套官方公开文件中的 10 个独立专题指引**，不是 10 家公司的内部制度。选取人力资源、资金活动、采购、资产、销售、工程项目、担保、全面预算、合同、信息系统，共保留 175 条完整条文。它适合首轮企业管理制度检索测试，后续应补充本公司的考勤、请假、差旅报销、费用审批等实际制度。

版本是 2010 年发布文本，资料快照日期为 2026-11-01。只评测对这套固定文本的理解，不据此判断现行法律效力，也不代表贵公司的实际授权、金额或期限。问题根据真实公开条文人工编写，模拟业务人员的实际提问，不是从生产用户日志采集。

## 文件用途

| 文件 | 用途 |
| --- | --- |
| `corpus/` | 10 份完整制度 Markdown，唯一应该上传的内容 |
| `仅上传知识库_10份制度资料.zip` | 上述 10 份文件的压缩包，先解压再上传 |
| `题库与标准答案.md` | 人工审阅题目、预期答案和依据 |
| `questions.jsonl` | 逐行 JSON 题库，方便程序读取与评分 |
| `sources.json`、`articles.json` | 来源、版本、哈希和条文映射 |
| `sources_raw/` | 下载的官方 PDF，用于核对 |
| `validation_report.json` | 离线核验结果，不是系统命中率 |
| `evaluate.py` | 离线核验及可选检索统计入口 |

**不要把标准答案、questions.jsonl、原始整本 PDF 或整个 evaluation 文件夹上传到知识库。** 上传答案会污染评测；整本 PDF 包含另外 8 份未选取指引，会改变资料范围。

## 导入步骤

1. 用管理员登录当前系统，解压压缩包，上传里面的 10 份 `.md` 文件。系统暂不支持直接上传 ZIP。
2. 在管理页面确认全部解析成功；检查主题、片段数量，然后为全部文档建立向量。
3. 确认每份文件的向量数等于片段数。`bge-m3` 必须完成权重准备并可正常编码，仅安装 Python 库还不够。
4. 测试时只选择这 10 份资料，每题使用新的对话，避免其他制度和聊天历史影响答案。不要把预期答案放入提示词。
5. 固定文档、切分参数、Embedding 模型及版本、检索数量、DeepSeek 模型 ID 和提示词，再开始记录结果。修改任一项后保存为新一次实验。

## 统计口径

| 指标 | 计算方式 | 说明 |
| --- | --- | --- |
| 文档 Hit@k | 前 k 条出现任一预期文档的题数 ÷ 40 | 较宽松，同一文档里找错条款也可能算命中 |
| 完整证据 Hit@k | 前 k 条覆盖该题全部必需摘录的题数 ÷ 40 | 建议作为首轮主要命中指标；跨文档题需全部覆盖 |
| 证据 Recall@k | 每题命中的必需摘录数 ÷ 该题必需摘录总数，再对 40 题取平均 | 展示遗漏了多少依据 |
| 回答正确率 | 必答要点全部满足且无实质错误的题数 ÷ 40 | 人工判定，不能拿检索命中代替 |
| 资料不足处理正确率 | 正确说明缺失信息且未编造的题数 ÷ 4 | Q041–Q044 单独统计，排除在检索命中率分母外 |

@1、@3、@5 分别取前 1、3、5 个片段。即使一次接口请求失败，这道有答案的题也保留在分母中，按未命中计，同时记录失败题号。批量运行前如果文档缺失、重名或向量未建好，脚本直接报错，不产生看似有效的评分。

证据匹配使用“正确来源文件 + 去空白后原文摘录完整包含于某个返回片段”，不以关键词相似直接判正确。若使用重写、摘要或不同分块方式，可能出现语义支持但未完整包含摘录的情况，应额外人工复核，不能把本脚本当成语义裁判。

人工检查回答时允许同义表达，但必须保留“应当/可以/不得”、适用条件、例外、职责分工与流程顺序；凭空补出金额、天数、审批人等应判错。资料不足题可以说明已有原则，再明确缺少公司具体规则，并请求补充。

## 离线核验与可选自动统计

在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m evaluation.enterprise_v1.evaluate validate
```

该命令核对 10 份资料、44 道题、所有原文引文、条款归属、PDF 页码、字符位置、文件哈希和压缩包内容，不连接模型、不修改应用数据库。

资料导入并建立向量后，可手动运行以下命令，密码会在终端隐藏输入，不写入结果文件：

```powershell
.\.venv\Scripts\python.exe -m evaluation.enterprise_v1.evaluate retrieval --username admin --output evaluation/enterprise_v1/results/retrieval_001.json
```

脚本限定 10 份资料范围，对 44 道题逐一调用现有 `/api/search`，计算 40 道有答案题的 @1/@3/@5 指标。记录模型信息、数据集哈希、实际文档 ID、片段快照、返回结果及错误。输出文件必须是新路径，保留以前的实验结果。

这一步会使用当前配置的 Embedding 服务；若配置为远程服务，会产生相应调用。它不调用 DeepSeek 生成回答，也不上传或修改知识库文档。该统计针对直接检索接口；Agent 多轮检索、邻接片段扩展和最终回答需要另外评测。

结果中的 `actual_answer`、`answer_correct`、`refusal_correct` 初始为 `null`，留待实际问答和人工复核。`null` 表示未评估，不能当作通过或不通过。人工记录时同时保存实际回答、引用片段、判断理由和错误类型（检索漏召回、证据不完整、条件理解错误、编造规定、接口失败等）。

**本目录提供固定资料、标准答案和离线一致性核验，不附带 DeepSeek/bge-m3 的实际命中率。** 新安装的发布版本不会自动导入资料，应自行按上述步骤上传并测量；数据准备状态与每个部署实例的实际导入状态是两回事。

## 重建资料

```powershell
.\.venv\Scripts\python.exe -m evaluation.enterprise_v1.build_sources
.\.venv\Scripts\python.exe -m evaluation.enterprise_v1.build_questions
```

重建会覆盖生成的题库、来源清单和压缩包。已有原始 PDF 时使用本地快照；缺失时从官方 URL 下载。改动题目或资料后，重新离线核验并保留新的版本记录。
