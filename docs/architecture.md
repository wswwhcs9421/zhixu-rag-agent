# 架构与数据流程

## 目录职责

| 目录 / 文件 | 职责 |
| --- | --- |
| `run.py`、`start.ps1` | 启动服务、Windows 基础安装 |
| `rag_agent/app.py` | API、认证与授权、会话归属、管理操作 |
| `rag_agent/config.py` | `.env` 与运行配置 |
| `rag_agent/documents.py` | PDF / 文本解析、结构识别与片段生成 |
| `rag_agent/knowledge.py` | 文档处理任务、SQLite、向量检索与词法融合 |
| `rag_agent/providers.py` | DeepSeek 及本地 / API Embedding 调用 |
| `rag_agent/agent.py` | 工具调用循环、证据注册与回答约束 |
| `rag_agent/citations.py` | 按首次引用重排来源，防止未知编号被发布 |
| `web/` | 无构建步骤的界面、安全转义与引用交互 |
| `evaluation/` | 公开测试资料、标准答案与离线检验，独立于正式知识库 |

## 文档到向量

上传原文件保存至 `data/uploads/`，文本解析后生成主题、章节路径、页码与从 1 开始的片段序号。切分优先遵守条款、标题、问答、列表、表格和代码结构，最后才按段落、句子及字符长度兜底。默认每片最多 1000 字符，同一长段内最大重叠 120 字符。

解析不会调用 LLM，也不会自动向量化。管理员检查片段后点击建立向量，bge-m3 为每个片段生成一个 1024 维稠密向量。向量归一化后与片段一起保存在 SQLite；这里没有使用 bge-m3 的稀疏或多向量模式。

编辑片段会删除对应旧向量；重新解析会替换原片段并清空文档向量。切换 Embedding 配置时，配置指纹不一致的旧向量不参与当前检索。

## 问题到答案

Agent 强制首次调用知识检索工具。`search_knowledge` 将问题编码，结合余弦相似度候选与 BM25 候选，通过 RRF 名次融合返回片段。模型可改写查询再次检索，也可通过 `read_document_section` 读取本轮已经发现片段的前后文。检索范围始终受请求中的文档范围约束。

默认最多 3 轮工具选择、6 次工具调用，总问答超时 180 秒。工具不会替用户修改文档、执行命令或访问任意外部地址。

模型使用本轮证据作答；后端先拒绝不存在的引用编号，再按引用首次出现顺序统一编号为 S1、S2…。引用快照记录文件名、真实片段号、文本、章节与页码。例如 `S1 · D10_信息系统.md · 片段 7` 表示本次答案的第一个来源，原文实际位于该文件的第 7 个片段。

历史快照不会被文档后续修改覆盖。早期记录若未保存片段号，只在能核对实际片段归属时补充；无法核实时明确标注未记录。

## 权限与运行范围

FastAPI 后端进行身份与角色校验，管理员与只读成员共用一个知识库，个人聊天历史按用户隔离。没有部门、文档级 ACL 或多租户隔离。

SQLite 与 NumPy 的实现适合小规模验证，不是大规模近似最近邻索引。RRF 也不是学习型重排器。编号有效不代表语义必然支持结论，真实回答效果应另行评测。
